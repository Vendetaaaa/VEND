# Overview

VEND is built around a simple idea: assembly should stay close to the machine, but the compiler should be responsible for the bookkeeping humans are bad at doing by hand.

## Why VEND Exists

Traditional assembly gives you full control, but it also makes you manually track:

- which register is holding which value
- when a sub-register overlaps another one
- whether a value fits the operand width you are using
- whether the control flow is still understandable a week later

That works for small snippets. It becomes painful when the codebase gets larger, when more people need to read it, or when the assembly is generated by a tool and still needs to be audited.

## What VEND Solves

VEND is trying to make assembly safer without turning it into something else.

It is designed to catch:

- silent register clobbering through lexical alias scopes
- sub-register conflicts through explicit physical-register tracking
- width mismatches through a strict `reg64` / `reg32` / `reg16` / `reg8` model
- control-flow mistakes through structured `if` and `while` forms
- confusing memory operands through explicit addressing syntax

## Why This Is Useful as a Published Tool

This is not meant to be a private experiment.

If VEND is useful, it should be something other people can read, try, fork, and improve. That means the repository needs to feel like a real open-source project: clear documentation, a predictable roadmap, and enough structure that contributors can understand the language without guessing.
